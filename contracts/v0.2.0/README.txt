Quanta 세부 명세 패키지 v0.2

상태
이 묶음은 구현을 위한 계약과 결정 기록이다. 계산 엔진·HTTP 서비스·미래 확장 기능을 구현했다는 뜻이 아니다. 명세 검사, 환경 버전 확인, 수치 합격 시험, 실제 조건의 물리 검증을 구분한다.

새 결정 기록
- decisions.json: DEC-001~DEC006의 확정된 설계 선택과 적용 원칙.
- expansion_candidates.json: EXT-001~EXT006의 추진 조건·선행 결정·후속 결정. 모든 후보는 candidate / not_started.
- development_baseline.json: 로컬에서 확인한 CPython 3.12.14, NumPy 2.3.5, SciPy 1.17.0을 사용한 초기 기준선과 필수 고정 절차.

계약 사용
공통 실험·실행·결과 계약과 각 모듈의 적용 범위를 구분한다. 입력·모듈·관측량·상태 포트·결과 스키마와 의미 검증 규칙을 함께 적용한다. 자료형·형상·단위가 같아도 상태의 물리적 의미가 다르면 자동 연결하지 않는다. 변환기와 물리적 결합은 각각의 계약과 검증 근거가 필요하다.

에너지·힘 계산의 도함수는 단일 AST forward automatic differentiation을 기본으로 한다. 해석적 기준식과 유한차분은 독립 검증용이며 운영 계산의 조용한 대체가 아니다. 관측량 선택은 필수 진단이나 다음 단계에 필요한 상태 스냅샷을 제거하지 않는다.

재현 기준선
Linux x86_64 CPU, 단일 워커·단일 thread를 초기 실행 정책으로 둔다. 실제 thread 수와 BLAS·LAPACK 구현은 구현 환경에서 확인해 기록한다. 로컬 버전을 관측한 것만으로 환경이 완전히 동결되거나 계산 검증이 통과했다고 표시하지 않는다.

표준 JSON Schema 검증기와 RFC 8785 구현의 정확한 의존성 버전은 아직 고정하지 않았다. 이 상태는 development_baseline.json에 unresolved_required_before_numerical_implementation으로 명시한다. 수치 모듈 구현 전에 정확한 직접·전이 의존성·배포 파일 해시·잠금 파일, 구현 Git 커밋, 시험 개정본, 실행 이미지 digest를 고정해야 한다. 이는 정해진 구현 준비 절차이며 미해결 값을 무시하거나 일반 직렬화로 대체하지 않는다.

미래 확장
시간 변화, 확률·통계, 다중 실험계·모형 결합, 대규모 계산·데이터, 사용자 코드·외부 엔진, 공동 연구는 별도 후보로 관리한다. 현재 지원으로 표시하지 않는다. 각 후보의 필요성과 선행 계약·검증 자료가 확보되면 해당 확장의 세부 설계를 시작한다.

수치·물리 검증
계약 작성이나 버전 조회는 계산 합격의 근거가 아니다. 검증 항목의 실행 상태와 실제 측정값을 보존하고, 작업 완료·수치 수렴·해상도 수렴·물리 검증 상태를 구분한다. v0.2를 작성했다는 이유로 과거 실행의 입력·버전·판정을 바꾸지 않는다.

문서와 계약 파일
문서 링크는 document_links.json에 보존한다. experiment.schema.json 공통 envelope만 검사해 실행하지 않으며 registry.json의 정확한 모듈 definition 스키마를 함께 적용한다. module_inputs.schema.json은 초기 모듈의 전용 제약을 담는다. 결과는 result.schema.json 및 module_results의 상세 스키마를 함께 검사한다. hashing_contract.json의 서로 다른 해시 대상과 제외 필드를 따른다. 이전 0.1.0 입력은 원본을 보존하고 새 0.2.0 개정본으로 명시적으로 변환한다.
