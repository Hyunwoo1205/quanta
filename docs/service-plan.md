# 실행 서비스 구현 계획

작성일: 2026-11-04 · 기준 소스: `8cb74d8090f537efd7ef0002064a4a9606009941`

기존 계산 모형과 입력 계약 0.2.0을 유지하면서 실행 HTTP API, 불변 revision·실행·산출물 저장, 단일 비동기 작업자를 구현합니다. Python 표준 라이브러리의 SQLite·HTTP·자식 프로세스를 사용하며 새 의존성은 추가하지 않습니다.

| 순서 | 구현과 완료 기준 |
|---|---|
| 1 | 소유자 범위의 실험·불변 revision, 수락 시 고정한 계획, 실행 기록과 산출물을 SQLite에 저장 |
| 2 | 계약의 조회·검증·실행·재실행·취소·capabilities 경로와 인증된 산출물 다운로드 제공 |
| 3 | 24시간 멱등성, 대기열 한도·시간 초과, 프로세스 간 단일 작업자, 재시작 복구 구현 |
| 4 | 계산 진행 상태·협력적 취소를 기존 엔진에 연결하고 취소와 완료의 원자적 경쟁 검증 |
| 5 | 실제 HTTP→작업자→수치 결과→재실행, 접근 경계·장애·회귀·설치 패키지·CI 검증 |

서버에서 식별자를 발급하고 인증 토큰을 고정 소유자에 연결합니다. 외부 식별자는 모두 같은 404로 처리합니다. 원본 입력과 수락한 계획을 보존하며 실행·재실행 전에 현재 신뢰하는 구현 및 등록부가 고정한 바인딩과 같은지 확인합니다.

SQLite 트랜잭션에서 먼저 확정된 종료 또는 취소 요청이 우선합니다. `CANCEL_REQUESTED` 이후 성공을 공개하지 않습니다. 계산 내부 취소는 기존 검사 지점에서 처리하며 검증된 완료 단계의 근거를 보존합니다. 자식 프로세스의 강제 종료에는 근거 없는 부분 결과를 만들지 않습니다.

서비스는 한 호스트·로컬 디스크의 단일 소유자 개발용 API입니다. 루프백 HTTP와 bearer 인증을 제공하고 실제 계정 서비스·공개 HTTPS 배포·분산 작업자·웹 화면·부분 체크포인트 재개는 다음 범위로 둡니다. 실제 현상에 대한 물리 검증 상태는 계속 `unvalidated`입니다.
