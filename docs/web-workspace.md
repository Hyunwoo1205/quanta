# 브라우저 연구 작업 공간

개발 패키지 `0.7.0`은 실험 정의·입력 검증·불변 입력 저장·실행 진행·수치 결과·근거 다운로드를 같은 화면에서 제공합니다. 기존 Python 계산기와 로컬 실행 서비스를 사용하며 새 계산식이나 물리적 검증 범위를 추가하지 않습니다.

## 시작하기

README의 잠금 설치를 완료한 Linux x86_64·CPython 3.12.14 환경에서 다음을 실행합니다. 아래 토큰 입력은 터미널에 표시되지 않습니다. 본인이 입력한 32자 이상의 토큰을 브라우저에도 입력합니다.

```bash
source .venv/bin/activate
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 NUMEXPR_NUM_THREADS=1
read -rsp 'API 토큰 (32자 이상의 가시 ASCII): ' QUANTA_API_TOKEN
echo
export QUANTA_API_TOKEN
quanta serve --store .cache/local-service --port 8765
```

서버를 실행한 컴퓨터의 브라우저에서 `http://127.0.0.1:8765/`를 열고 연결합니다. API는 계속 `/v1`에 있습니다. Node는 프런트엔드 회귀 시험 도구이며 서버나 브라우저 사용에 설치할 필요가 없습니다. 별도 JavaScript 의존성·CDN·프런트엔드 빌드도 없습니다.

현재는 루프백 개발용 웹 앱입니다. 다른 컴퓨터·공개 URL·외부 계정으로 제공하는 배포는 별도 단계입니다. 클라우드 호스트의 `127.0.0.1`이 사용자 컴퓨터를 뜻하지 않는 점을 구분해야 합니다.

## 실험 구성부터 결과까지

1. **예제 불러오기 또는 JSON 가져오기:** 에너지·힘, 정적 탐색, 양자 정적 상태와 다단계 예제 다섯 개를 제공합니다. JSON 정의 전체를 편집할 수 있습니다.
2. **입력 검증:** 서버의 등록 스키마·단위·수식·지원 범위·자원 한도로 검증합니다. 오류 코드와 JSON Pointer를 표시하며 미지원 내용을 임의 수정하지 않습니다.
3. **새 입력 저장:** 실험을 만들거나 현재 실험의 새 불변 revision으로 저장합니다. 기존 저장 입력을 덮어쓰지 않습니다. 수정 중인 내용과 저장한 입력은 구분합니다.
4. **실험 실행:** 저장한 revision을 실행합니다. 요청 응답이 불확실한 경우 같은 멱등성 키로 재시도해 실행 중복을 방지합니다.
5. **진행·기록 조회:** 처리 단계와 활성 단계를 표시합니다. 실행 취소·동일 입력 재실행을 요청하고, 새로 연결한 뒤에도 서버의 실행 기록을 다시 조회할 수 있습니다.
6. **결과 탐색과 다운로드:** 분기·단계별 실제 payload, 상태 판정, SI 단위의 수치와 그래프를 확인하고 원본 결과·산출물을 내려받습니다.

표시하는 수치는 서버의 실제 결과에서 가져옵니다. 시작 전에는 계산 결과를 만들지 않습니다. 입력이 바뀐 상태에서는 다시 저장한 뒤 실행해야 합니다. 늦게 도착한 요청이 다른 실험·실행·편집 내용을 덮어쓰지 않도록 선택과 요청 세대를 검사합니다.

## 수치와 그래프의 의미

| 결과 | 표시 |
|---|---|
| 공통 | 실행 상태, 수치 수렴, 격자 해상도 수렴, 물리적 검증 상태를 개별 표시 |
| 에너지·힘 | 총에너지 J, 입자별 힘 N, 고정 좌표의 반력과 최종 좌표 m |
| 정적 탐색 | 최종 에너지·자유 기울기·종료 사유, 수락한 반복의 실제 이력 |
| 양자 정적 상태 | 에너지 J, 상태별 파동함수 m^-1/2와 확률밀도 m^-1, 위치 m |
| 불완전 실행 | 성공한 이전 단계의 근거와 실패·취소 진단, 계산 결과가 없으면 명확한 빈 상태 |

그래프의 선은 저장된 이산 자료의 시각화입니다. 중간 점을 새 계산이나 물리적 시간 변화로 해석하지 않습니다. 매우 작은 SI 수치를 0으로 반올림해 숨기지 않습니다. 원본 데이터 확인에는 결과 JSON과 산출물 다운로드를 사용합니다. 물리적 검증 상태는 계속 `unvalidated`입니다.

## 입력·인증 보존

브라우저에서 JSON을 정렬하고 저장 요청을 만들 때 원문의 숫자 토큰을 보존하며, 저장된 revision은 서버 응답의 정의 부분을 직접 불러옵니다. 서버의 JSON 저장 후 지수 표기나 공백은 달라질 수 있습니다. `-0`, `-0.0`의 명시적인 부호는 실제 기록에 보존하고 과학 해시의 JCS 정규화 규칙은 유지합니다. 원본 결과 다운로드는 수치를 다시 직렬화한 표가 아니라 서버 응답 bytes를 사용합니다.

토큰은 열린 페이지의 메모리에만 보관하고 로컬 저장소·세션 저장소·쿠키·URL·로그에 기록하지 않습니다. 새로고침하면 다시 연결해야 합니다. 서버의 API 인증과 소유자 확인은 그대로 유지합니다. 정적 HTML·예제에는 개인 입력·실행 결과나 토큰이 들어 있지 않습니다.

서버는 정적 파일을 정확한 허용 경로에서만 제공하고 Host·Origin, 요청 크기와 프레이밍을 검사합니다. 콘텐츠 보안 정책은 같은 출처의 스크립트·스타일만 허용합니다. 가져온 제목·오류·JSON은 코드로 실행하지 않습니다.

## 검증

Python 회귀 시험은 정적 자원·동일 출처·인증·실행 기록·불변 입력을 검사합니다. Node `24.22.1`의 내장 시험은 상태 구분·숫자 보존·오류 입력·그래프 좌표 변환을 확인합니다. `scripts/verify_web.py`의 W01~W05는 실제 HTTP·SQLite·계산 자식 프로세스로 저장·실행·재조회·산출물 해시를 독립 기준과 비교합니다. 이 HTTP 검증을 브라우저 렌더링 검증으로 대신 표시하지 않습니다. 실제 검증 결과와 브라우저 확인 범위는 `runtime_manifest.json`에 기록합니다.
