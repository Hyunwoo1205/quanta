# 비공개 클라우드 파일럿 배포 계획

갱신일: 2026-11-05 · 출발 소스: `959dc2cfceb1e271ee99e7fe6b6e598d4f4d3d43` · 상태: ARM 검증 완료, 운영 인증·HTTP 검증 단계 통과

## 목표와 범위

첫 배포는 **본인 한 명만 로그인해 사용하는 비공개 연구 작업 공간**으로 만듭니다. 브라우저에서 실험 작성 → 검증 → 저장 → 실행 → 결과·원본 다운로드를 완료하고, 서버 재시작과 백업 복구 후에도 기록을 보존하는 것이 목표입니다.

사용자가 **OCI 단독 배포**를 선택했습니다. 화면·API·계산 작업자·SQLite를 OCI VM 한 대에서 운영합니다. 로그인·HTTPS 진입점의 기본안인 Cloudflare Access·Tunnel은 접속을 담당하고, 앱과 계산·DB는 OCI에서 실행합니다.

현재 개발 패키지는 `0.10.0`, 입력 계약은 `0.2.0`입니다. ARM 지원 준비는 [실행 프로필](arm-runtime.md)과 [0.8.0 검증](arm_runtime_verification.json), 운영 인증·HTTP는 [사용법](production-access.md)과 [현재 검증](production_access_verification.json)에 구현·측정을 구분합니다. 영속 볼륨 마운트 확인·비 root 실행·재시작·백업 복구 구성은 [운영 절차](operations.md)에 구현하며 실제 OCI 사용 환경 검증과 구분합니다. 사용자가 OCI 준비 완료를 알렸으며, 접속 주소·사용자·OS·안전한 인증 경로와 실제 볼륨 구성은 아직 전달받지 못했습니다. 이 작업에서 원격 접속·도메인 변경·클라우드 배포는 아직 수행하지 않았습니다. 기존 계산 모형·정밀도·수치 기준을 유지하며 물리 검증 상태는 계속 `unvalidated`입니다.

단계 1의 0.8.0 네이티브 CI는 구현 commit `2265913`에서 x86·ARM 각각 Python 456개·Node 25개와 여섯 측정·설치 컨테이너 검증을 통과했습니다. 0.9.0은 단계 2의 Access·ASGI·세션 화면을 구현하고 두 CPU에서 각각 Python 573개·Node 33개, 새 의존성·일곱 측정·설치 컨테이너 검사를 통과했습니다. 중단 후 재조회한 GitHub 전체 실행 상태도 completed/success임을 확인했습니다. 최초 조회의 표시 지연은 보존 기록에 남깁니다. 실제 OCI A1 성능·원격 접속·배포·복구 확인과 구분합니다.

## 선택한 구성과 무료 한도

| 항목 | 첫 배포의 선택 | 이유·조건 |
|---|---|---|
| 호스트 | OCI `VM.Standard.A1.Flex`, Linux ARM64, 2 OCPU·12 GB RAM | 홈 리전의 Always Free 자원 잔여 한도·생성 가능 여부 확인 필요 |
| 진입점 | 소유한 도메인의 HTTPS 주소 하나 | 화면·API·산출물 다운로드를 같은 출처로 제공 |
| 로그인 | Cloudflare Access, 본인 이메일만 허용, 이메일 일회용 코드 | 초기에는 별도 비밀번호 저장·회원가입 없이 접속 |
| 원본 연결 | Cloudflare named Tunnel → 호스트 내부 HTTP | 계산 서버의 HTTP 포트를 인터넷에 직접 열지 않음 |
| 앱 | 운영용 ASGI 어댑터 + Uvicorn 프로세스 1개 | 기존 실행 서비스와 단일 계산 감독자 재사용 |
| 계산 | 동시에 자식 프로세스 1개, 수치 스레드 1개 | 현재 자원·대기열 정책 유지 |
| 영속 저장 | 부트 볼륨 50 GB + 데이터 볼륨 150 GB 기본안 | VM에 연결한 데이터 볼륨의 파일시스템에 SQLite·기록 보관 |
| 백업 | SQLite 일관된 스냅샷 + OCI 관리형 볼륨 백업 | DB 일관성 검증과 호스트 밖 복구 사본을 함께 확보 |

2026-11-04 Oracle Always Free 전용 문서 기준 A1 무료 월 합계는 1,500 OCPU시간·9,000 GB시간이며, 2 OCPU·12 GB 구성에 해당합니다. 운영 볼륨은 부트·데이터 합계 200 GB, 관리형 볼륨 백업은 부트·데이터 합계 5개가 홈 리전의 별도 무료 한도입니다. 같은 계정의 기존 사용량도 포함해 Console에서 실제 잔여 한도·Always Free 표시와 생성 예상 비용을 확인합니다. Cloudflare Access 무료 요금제를 기본안으로 두되 도메인과 한도 초과·추가 서비스까지 무료라고 가정하지 않습니다.

이 크기는 단일 사용자 파일럿의 **초기 가정**입니다. A1 확보 가능성은 무료 한도와 별개이고, 사용량이 낮은 Always Free 인스턴스는 Oracle 정책에 따라 회수될 수 있습니다. 재생성·백업 복구 절차를 마련하고 실제 A1에서 계산 시간·최대 메모리·동시 HTTP 응답을 측정합니다. 단일 VM 장애 시 서비스 중단을 허용하는 초기 구성입니다.

프런트엔드만 따로 배포하거나 분산 큐·네트워크 SQLite를 도입하지 않습니다. SQLite WAL은 같은 호스트에서 사용해야 하고, 현재 계산기는 네이티브 Python 의존성·자식 프로세스·Linux 자원 제한을 사용합니다. Cloudflare Workers에 현재 엔진을 그대로 올리는 방식은 이번 배포안에 맞지 않습니다.

ARM 프로필·잠금·이미지 준비와 운영 인증·백업 도구 구현은 서버 접속 전에 진행할 수 있습니다. 실제 ARM 계산 검증에는 A1 또는 동등한 실제 ARM 실행 환경이 필요하며 x86 실행·교차 다운로드·에뮬레이션만으로 통과를 선언하지 않습니다. 0.8.0에 ARM 실행 준비를 구현하고 검증 결과는 별도 기록에 남깁니다. 운영 인증·백업 구현은 다음 개발 단위입니다.

## 0. ARM 실행 환경 추가

0.7.0의 Dockerfile·잠금·환경 검사는 Linux x86_64 전용이었습니다. 0.8.0에 별도 ARM 이미지·잠금·실행 프로필을 추가하며 실제 검증 상태는 위 기록을 따릅니다. 기존 x86 패키지를 A1에 그대로 복사해 실행하는 방식으로 처리하지 않습니다.

- 기존 x86_64 프로필과 측정 기록을 보존하고 Linux ARM64용 실행 프로필을 별도로 추가합니다. 가져온 개발 기준의 과거 기록을 ARM 검증 기록으로 덮어쓰지 않습니다.
- CPython 3.12.14와 기존 의존성 버전의 ARM wheel·공식 해시·이미지 digest를 확인해 아키텍처별 잠금과 설치 절차를 마련합니다. 필요한 배포가 없으면 기준 변경을 검토·기록하고 버전을 자동 변경하지 않습니다.
- 실제 ARM에서 전체 회귀·A·SI·B·WF·S·W 측정·설치 패키지·컨테이너 흐름을 확인합니다. 수치 허용오차는 유지하고 코드·환경·배포 파일·측정 해시를 새로 기록합니다.
- 기존 x86 실행의 결과 조회·다운로드는 보존하되, 엄밀한 replay는 일치하는 기존 신뢰 환경이 필요합니다. ARM 전환 후 같은 계획·환경으로 재현했다고 표시하지 않습니다.

## 1. 운영 인증과 HTTP 경계

현재 `quanta serve`는 루프백 전용 `http.server`와 메모리 bearer 토큰을 사용하는 개발 어댑터입니다. Host·Origin도 localhost에 한정되고 브라우저 요청은 `credentials: 'omit'`입니다. 도메인만 연결해서 공개할 수 없으므로 운영 어댑터를 추가합니다.

- 기존 계산·저장 서비스는 재사용하고 공개 요청 처리를 얇은 ASGI 어댑터에 연결합니다. Uvicorn은 `workers=1`, 자동 reload 없이 실행합니다. 개발용 루프백·bearer 모드는 유지합니다.
- 공개 HTTPS origin과 호스트명을 설정에 고정합니다. 신뢰하는 Tunnel 경로 외의 전달 헤더를 신뢰하지 않으며 Host·Origin 검사를 와일드카드로 완화하지 않습니다. 변경 요청은 같은 출처·허용 Content-Type 경계를 검사합니다.
- 원본 요청 bytes를 기존 엄격한 파서에 전달합니다. 1 MiB 입력 제한·중복 키·비유한 수 거부, 정수·실수 토큰과 `-0` 부호 보존을 유지합니다. 프레임워크의 자동 JSON·숫자 변환으로 과학 입력을 바꾸지 않습니다.
- Access 애플리케이션과 본인 이메일 허용 정책을 **공개 라우트보다 먼저** 구성합니다. `cloudflared`의 Access 검증도 켜고 앱에서도 `Cf-Access-Jwt-Assertion`의 서명·고정 알고리즘·issuer·audience·유효 기간을 검증합니다. 알려진 팀의 JWKS 주소만 사용하고 키 캐시·교체·갱신 빈도 상한을 처리합니다. 임의 이메일 헤더나 토큰의 원격 키 URL을 신뢰하지 않습니다.
- 검증한 허용 외부 계정을 기존 내부 소유자 `local`에 명시적으로 연결하여 현재 실험 기록을 승계합니다. 신원 누락이나 다른 계정에 기본 소유자를 부여하지 않습니다. 다중 사용자 가입·공유는 별도 확장입니다.
- 운영 화면은 API·산출물 요청 모두 `credentials: 'same-origin'`으로 로그인 세션을 사용합니다. 토큰을 수동 입력하거나 브라우저 영구 저장소에 보관하지 않습니다. 실험·실행·다운로드 전체에 같은 인증·소유권 검사를 적용합니다.
- 로그인 만료·로그인 HTML 응답·인증 리다이렉트를 정상 계산 결과로 처리하지 않습니다. polling을 멈추고 재로그인을 안내하며, 미저장 입력은 현재 화면에서 보존하거나 이동 전에 내보낼 수 있게 합니다. 재로그인 후 서버 기록을 다시 조회하고 계산을 자동 중복 제출하지 않습니다. 로그아웃은 이미 수락한 서버 계산을 취소하지 않습니다.

Uvicorn·JWT 검증 등 새 의존성이 필요하면 구현 단계에서 유지되는 공식 버전을 확인하고 모든 전이 의존성의 wheel 버전·해시를 아키텍처별로 잠급니다. CPython·과학 계산 의존성의 버전과 수치 기준은 ARM 지원을 이유로 조용히 바꾸지 않습니다.

## 2. 컨테이너·데이터·운영 상태

Dockerfile의 기본 명령은 계약 검사이며 운영 서버 시작은 deploy/oci의 systemd 구성으로 분리합니다. 이미지 기본 UID/GID는 10001:10001입니다. 비 root 앱, 고정 이미지 digest, 비밀 설정 분리, 재시작 정책과 정상 종료를 포함합니다. 실행 토큰·Tunnel 자격 증명·백업 키를 git·이미지·URL·로그에 넣지 않습니다.

HTTP 프로세스 하나가 계산 감독자 하나를 시작하고 기존 프로세스 간 독점 잠금을 유지합니다. HTTP worker나 복제본을 늘려 계산 감독자가 중복되는 배포를 금지합니다. DB는 데이터 볼륨을 마운트한 단일 호스트의 파일시스템에 두고 권한·여유 공간을 확인합니다. 데이터 볼륨이 없으면 부트 디스크의 빈 디렉터리에서 새 DB를 자동 생성하지 않고 시작을 거부합니다.

기존 계산 자식의 주소 공간 1,024 MiB·벽시계 120초·단일 수치 스레드와 대기열 정책을 유지합니다. 호스트의 12 GB RAM을 이유로 계산 상한을 자동 확대하지 않습니다. 컨테이너 전체 제한은 HTTP·감독자·자식과 호스트 여유를 포함해 실제 측정 후 설정합니다. 계산 결과를 빨리 얻기 위해 수치 판정이나 자원 상한을 조용히 변경하지 않습니다.

운영 상태 점검은 HTTP 응답만 확인하지 않습니다. 감독자 thread 생존·치명적 오류, DB 접근 가능 여부와 디스크 여유를 readiness에 반영하고, 상세 진단은 외부에 공개하지 않습니다. 작업자 오류·반복 재시작·백업 실패·디스크 부족을 운영 기록에서 확인할 수 있게 합니다. 입력 전문·인증 헤더를 기록하지 않고 request/run ID·오류 코드·시각으로 추적합니다.

## 3. 백업·업그레이드·롤백

- 실행 중 DB는 Python SQLite backup API 등 일관된 스냅샷 절차로 보관합니다. 활성 DB 파일 하나만 복사해 WAL 변경을 빠뜨리지 않습니다. 저장된 실험·불변 revision·고정 계획·실행 이력·산출물이 함께 복구되어야 합니다.
- 닫힌 DB 스냅샷과 해시·환경 manifest를 데이터 볼륨에 보존한 다음 OCI 데이터 볼륨을 백업합니다. 서버 내부의 논리 DB 사본·임시 파일은 실제 디스크 여유를 사용합니다. OCI 관리형 백업은 운영 볼륨의 200 GB 밖에 저장되며 crash-consistent이므로 애플리케이션 일관성 검증을 대체하지 않습니다.
- 관리형 백업 초기안은 부트 1개·데이터 최근 3개를 유지하고 나머지 1개를 교체·업그레이드 직전에 사용합니다. 같은 계정의 다른 부트·데이터 백업을 포함해 총 5개를 넘지 않도록 조정합니다. 검증한 복구 지점을 유지하며 오래된 백업을 순환하고, 기존 정상 데이터는 자동 삭제하지 않습니다. 논리 DB 사본의 개수는 별도의 디스크 여유 예산으로 정합니다. 별도 Object Storage 버킷에 파일을 내보내면 해당 저장·요청 한도도 따로 계산합니다.
- 목표 RPO는 24시간, 목표 RTO는 1시간입니다. 이는 **복구 시험 전의 목표**이며 보장된 실측치가 아닙니다. 별도 디렉터리 또는 대체 VM에 복원해 SQLite integrity와 기록·산출물 해시, 실제 조회·다운로드를 확인하고 소요 시간을 남깁니다.
- 첫 실사용 전에 한 번 복구하고, 이후 스키마 변경·배포 절차 변경 때 다시 확인합니다. 원본 데이터를 복구 시험으로 덮어쓰지 않습니다.

부트 50 GB·데이터 150 GB를 모두 할당하면 새 복원 볼륨을 동시에 만들 여유가 무료 200 GB 한도에 없습니다. 첫 DB 복구 시험은 기존 데이터 파일시스템의 별도 디렉터리에 충분한 여유가 있는지 확인한 뒤 논리 스냅샷으로 수행합니다. 이 시험을 관리형 볼륨 전체 복원 시험으로 표시하지 않습니다. 전체 볼륨 복원은 별도 용량·비용·안전한 교체 조건을 확정한 후 검증하고, 무료 한도를 맞추려고 유일한 정상 원본부터 삭제하지 않습니다. 한도 초과 자원을 이번 계획 확정만으로 생성하지 않습니다.

수락한 실행 계획은 패키지 버전과 전체 Python 구현에 묶입니다. 인증 어댑터를 추가하는 변경도 고정 구현 해시를 바꿀 수 있으므로 업데이트 시 새 실행 수락을 중지하고 대기·실행 작업을 비운 뒤 백업·이미지 교체를 수행합니다. 처리할 수 없는 고정 계획을 새 코드로 조용히 다시 계획하지 않습니다.

이전 이미지 digest·CPU 아키텍처·잠금·DB 버전을 함께 보관합니다. 이전 실행의 엄밀한 replay는 일치하는 신뢰 이미지와 실행 환경이 필요합니다. 여러 버전·아키텍처 replay를 현재 앱이 자동 분기하는 기능은 아직 없습니다. 필요할 때 이전 x86 환경·이미지와 백업 사본의 격리 실행 절차를 마련하고, 준비되지 않았으면 재실행 불가 이유를 명확히 표시합니다.

롤백은 단일 인스턴스를 멈춘 뒤 이전 이미지로 교체합니다. DB 스키마가 역호환되지 않으면 검증한 이전 백업을 사용하며, 복원 시점 이후의 기록 손실 범위를 먼저 확인합니다. 동일 SQLite에 구·신 버전을 동시에 연결하는 rolling 배포는 하지 않습니다.

## 4. 실제 검증과 완료 기준

기준 소스의 [CI 41829356124](https://github.com/Hyunwoo1205/quanta/actions/runs/41829356124)는 Python 399개·Node 25개 시험, 여섯 수치·서비스·웹 측정, 설치 wheel·컨테이너 실행을 통과했습니다. 기존 실제 브라우저 기록은 정적 데스크톱 확인이며 **인증된 브라우저 계산·모바일 검증의 근거가 아닙니다**. 운영 어댑터 구현 후 새 소스에 대한 회귀와 아래 검증을 따로 남깁니다.

| 영역 | 실제 확인할 동작 |
|---|---|
| 접근 | 허용 이메일 로그인, 미인증·다른 계정·만료/위조 JWT·잘못된 audience 거부, Host·교차 출처 요청 차단, HTTP 포트 직접 접근 차단 |
| 작성·실행 | 예제 선택, 원본 숫자와 `-0` 보존, 오류 표시, 저장 후 실행, 동일 멱등성 키 재시도로 중복 실행 없음 |
| 결과 | 쌍 계산·정적 탐색·양자·다단계 실행의 실제 표·그래프, 상태 구분, 원본 bytes·크기·SHA가 맞는 다운로드 |
| 상태 변화 | 진행·취소·새 replay, 연결 끊김·세션 만료·재로그인 후 기록 재조회, 미저장 입력 보호 |
| 화면 | 데스크톱 Chrome 및 실제 사용하는 모바일 Safari 또는 Chrome의 입력·표·그래프·다운로드·가로 넘침 |
| 장애·복구 | 정상 종료·재시작, 계산 자식 종료·감독자 실패 감지, 디스크 부족 시 기록 보호, 별도 위치 백업 복원 |
| 자원·재현 | 실제 A1의 wall time·메모리·HTTP 응답, 현재 A·SI·B·WF·S·W 기준과 ARM 환경/이미지/측정 해시 |

브라우저 자동화·모바일 viewport 검사는 보조 근거로 활용하되 실제 기기 검증과 구분합니다. 최소한 실제 배포 URL에서 로그인 → 검증 → 저장 → 계산 → 결과·다운로드와 재시작·복구가 확인되어야 파일럿 완료로 기록합니다. 확인하지 못한 기기·장애는 통과로 표시하지 않습니다.

## 실제 배포 전에 필요한 입력

OCI 계정·홈 리전·기존 A1 인스턴스 유무·OS·접속 사용자·네트워크 접근 허용과 안전한 인증 경로를 먼저 확인합니다. 현재 Work에 SSH 클라이언트는 있지만 실제 OCI 연결 가능 여부는 검증하지 않았습니다. 지원되는 원격 접속 경로가 설정되면 연결을 검사하고, 직접 접속이 지원되지 않으면 OCI Cloud Shell에서 실행할 설치 스크립트·GitHub 기반 배포 절차를 준비합니다. 비밀키를 채팅·소스·로그로 전달하지 않습니다.

실제 공개 진입점 구성 전에는 소유한 도메인·Cloudflare 계정, 허용할 로그인 이메일, 복구 키 보관 위치가 필요합니다. 무료 한도·기존 자원·데이터 이전 대상을 확인하고 별도 유료 자원은 구체적인 필요·비용을 정한 뒤 진행합니다. 이러한 값이 없어도 ARM 지원 준비와 운영 어댑터·컨테이너·백업 도구의 로컬 구현은 진행할 수 있습니다.
