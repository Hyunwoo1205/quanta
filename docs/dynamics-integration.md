# 독립 velocity-Verlet 시간적분

2026-11-06 · 개발 앱0.14.0 · 실행 요청 계약0.3.1 · 모듈0.1.0

이 문서는0.14.0의 독립 solver 구현 기록입니다.0.15.0의 일반 실험·저장·API 연결은 [동역학 실험 실행](dynamics-workflows.md)을 참고합니다.

연구자가 명시한 질량·초기 위치·전 스텝 속도와 동일한 거리 의존 쌍 퍼텐셜로 입자계의 시간 궤적을 계산합니다. 현재 진입점은 독립 Python 함수와 CLI입니다. 기존 다단계 실험·SQLite·비동기 API·브라우저 화면에 연결하는 작업은 다음 단계입니다. 기본 실험 계약0.2.0과 검증 전용0.3.0의 원본은 보존합니다.

```bash
quanta integrate-dynamics contracts/v0.3.1/examples/free.request.json --format text
quanta integrate-dynamics contracts/v0.3.1/examples/harmonic-refinement.request.json > result.json
python scripts/verify_dynamics.py --output .cache/dynamics_verification.json
```

Python API는 `quanta.dynamics.integrate_dynamics_request(request)`입니다. 입력 JSON을0.3.0에서 자동 변환하지 않습니다. `validate-dynamics`는0.3.0과0.3.1을 검증하지만 초기 힘 계산과 실제 시간적분 여부를 별도로 반환합니다. 실행 API는0.3.1만 허용합니다.

## 모형과 수치 정책

2~128개 입자, 자유로운3차원 비주기 경계, 명시적 양의 질량과 속도, 모든 입자쌍의 동일한 자율 퍼텐셜을 지원합니다. 외력·시간 의존 퍼텐셜·주기 경계·cutoff·열조절·구속·확률적 힘·양자 모형 결합은 지원하지 않으며 입력에서 거부합니다. 이 수치 모형의 실행 성공은 실제 물질이나 NVE 앙상블·온도·에르고딕성의 물리 검증을 뜻하지 않습니다.

입력·출력은 SI이며 계산은 명시한 L0/E0/T0에서 파생한 무차원 위치·속도·질량·힘을 사용합니다. 무차원 전 스텝 상태가 적분의 기준이며 SI 관측 프레임은 그 상태를 binary64로 변환한 값입니다. 출력 SI를 다시 나누는 반올림을 다음 적분 상태에 끼워 넣지 않습니다. 공용 힘 커널의 전방 자동미분과 기존 쌍 합산 순서를 사용합니다. 각 성분의 곱·합은 입력 binary64의 정확한 유리수 연산 뒤 한 번 반올림하며, 정밀도·상수·모형을 조용히 변경하지 않습니다.

half-kick → drift → 새 힘 평가 → half-kick 순서로 위치와 속도가 같은 시각인 전 스텝만 수락합니다. drift 선분 전체에서 모든 쌍의 최소거리를 검사하므로 두 끝점이 안전해도 중간에 최소거리 경계를 통과하면 실패합니다. 반사·좌표 clamp·자동 시간간격 조정은 없습니다. 시각은 반복 덧셈 대신 각 leg의 binary64 dt와 정수 인덱스의 정확한 곱을 반올림합니다.

## 진단·저장·해상도

에너지·운동량·각운동량·질량중심의 최대 편차는 저장 간격과 관계없이 모든 수락 스텝에서 검사합니다. 표본 간격은 저장할 프레임 수만 바꿉니다. 수치 허용오차 초과만으로 계산을 중간에 자르거나 시간간격을 바꾸지 않고, 요청된 계산 완료 뒤 `numerical_status`를 판정합니다.

세분화를 요청하면 같은 초기 상태에서 h/h2/h4 세 leg를 독립 실행합니다. 기본 결과는 h 궤적을 유지합니다. 모든 기본 정수 시각에서 위치·속도의 정규화 오차를 비교하며 보간하지 않습니다. 두 인접 차이가 각각 허용오차 이하이고 더 미세한 차이가 증가하지 않아야 해상도 통과입니다. 세분화 미요청 또는 미완료는 `resolution_status=not_checked`이며 미측정 오차는 null입니다.

초기 힘은 실제 적분에 재사용합니다. 기본 n스텝은 n+1회, 세분화는7n+3회의 힘 평가를 예약하며 시도/완료 횟수를 구분합니다. 총 힘 평가10,000회·쌍 연산1,000,000회·예약 프레임512개·실제 보고서32MiB 등 등록 상한과 더 낮게 요청한 보호 한도를 지킵니다. 독립 integrate 전체는 검증·provenance·세 leg·최종 게시를 포함한 한 단계이며60초 제한을 각 미세 스텝마다 갱신하지 않습니다.

## 실패·상태·재현

입력 실패는 궤적이 없습니다. 실행 중 오류는 완전히 수락된 스텝만 부분 궤적으로 보존하고, 필요하면 마지막 수락 프레임을 추가합니다. half-step·실패한 trial 좌표는 공개하지 않습니다. 취소는 진행 중 독립 실행의 미게시 결과를 폐기합니다. 자원 한도 때문에 유효하게 게시할 수 없는 결과도 성공으로 만들지 않습니다. 중간 solver 체크포인트 재개는 지원하지 않습니다.

입력 검증·실행·수치·해상도·물리 상태는 독립 필드입니다. 모든 조건을 통과한 `SUCCEEDED`에만 형식화한 최종 위상 상태를 제공합니다. 실패·미수렴·취소는 후속 계산용 성공 상태로 승격하지 않습니다. 물리 상태는 계속 `unvalidated`입니다.

보고서는 원본/정규 입력, 코드·계약·환경 잠금·관측 환경과 과학 상태의 해시를 분리합니다. 실행 전후 실제 코드·계약의 일치와 전체 compact UTF-8 JSON 보고서 바이트 한도를 확인합니다. 전송은 signed zero를 보존하며 CLI도 검사한 것과 같은 bytes로 출력합니다. 과학 해시는 별도로 RFC8785 정규화를 따릅니다. Python의 선택적 `step_observer`는 복사된 진단 프레임만 받는 신뢰된 측정 훅이며 JSON 입력 기능이 아닙니다. 훅의 존재를 provenance에 기록하고 실행 시간에 포함합니다. 콜백 오류는 명시적 실행 실패입니다.

새 패키지의 구현 지문은 과거 strict replay와 다릅니다. 과거 결과나 해시를 덮어쓰지 않고, 같은 입력을 현재 구현에서 계산할 때는 별도 새 실행으로 취급합니다.

## 실제 검증 범위

독립 측정은 자유 운동, 해석 가능한 두 입자 조화 운동의 전1,001개 시각, 시간간격 감소의2차 수렴, 회전·병진·입자 순열·척도 동등성, 명시적 속도 반전, 저장 간격 독립성과 drift 선분 오류를 포함합니다. 고정된 허용오차를 완화하거나 수식을 사후 보정하지 않습니다. 실제 수치·전체 회귀·ARM/x86·설치 경로 결과는 [검증 기록](dynamics_solver_verification.json)과 [WORKPLAN](../WORKPLAN.md)에 기록합니다.

D07의 drift 오류 하위 사례를 확인한 것을 전체 D07~D11의 실행 서비스·강제 취소·재현·운영·웹 통합 합격으로 확대하지 않습니다. 다음 작업은 단일 동역학 단계의 계획/실행/상태 전달·저장·취소/재현을 연결하고 해당 통합 기준을 검증하는 것입니다. 그 뒤 궤적·관측량의 웹 시각화를 구현합니다.
