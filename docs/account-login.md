# 서버 계정 로그인과 Gmail 인증

2026-11-06 · 개발 앱 0.12.0 · 과학 입력 계약 0.2.0

이 기능은 OCI의 Quanta 서버에서 아이디·비밀번호·세션을 관리합니다. Gmail은 가입 인증, 선택형 이메일 추가 인증, 비밀번호 재설정의 코드 발송에 사용합니다. Cloudflare 계정이나 별도 메일 도메인 등록은 이 경로의 필수 조건이 아닙니다. 실제 배포·실제 발송·실제 사용자 가입의 확인 상태는 WORKPLAN과 별도 실행 근거를 따릅니다.

## 가입과 소유권

사용자 결정에 따라 이메일을 인증한 누구나 가입할 수 있습니다. 아이디는 영문자·숫자로 시작하는 3~64자의 영문자·숫자·점·밑줄·하이픈이며 대소문자를 구분하지 않습니다. 비밀번호는 15~256자의 Unicode 문자열이고 UTF-8 기준 최대 1,024바이트입니다. 비밀번호 앞뒤 공백을 제거하거나 조용히 잘라내지 않습니다.

기존 소유자 키로 최초 관리자 이메일을 먼저 예약해야 가입 요청을 활성화할 수 있습니다. 그 이메일을 실제로 인증한 최초 소유자 계정만 기존 내부 소유자 `local`에 연결하며 이전 실험·입력·실행·산출물을 이어서 조회합니다. 다른 가입자는 `account-<임의 식별자>`의 별도 소유자로 등록됩니다. 사용자가 입력한 아이디나 이메일을 데이터 소유자 식별자로 직접 사용하지 않습니다. 다른 사람의 실험·기록·산출물은 계정 사이에 공유하지 않습니다.

소유자 키가 확인되고 관리자 계정이 아직 없는 동안에는 잘못 예약한 관리자 이메일을 교정할 수 있습니다. 새 이메일이 이미 가입한 계정에 속하면 거부하고, 변경 전 이메일의 가입 코드는 무효화합니다. 관리자 생성 뒤의 예약 이메일 변경이나 기존 일반 계정 승격은 이 절차에서 지원하지 않습니다.

## 최초 비공개 설정

1. 실제 HTTPS 사이트에서 **최초 관리자 설정** 또는 접힌 **소유자 메일 설정·복구**를 엽니다.
2. 현재 소유자 접속키, 기존 자료를 사용할 관리자 이메일, Gmail 발송 계정과 Google 앱 비밀번호를 입력합니다. 이 값은 사이트에서 서버로 직접 전송하며 채팅·GitHub·작업 로그에 보관하지 않습니다.
3. 설정을 저장한 뒤 예약한 관리자 이메일로 가입 인증번호를 요청합니다. 메일을 받아 인증번호·가입 아이디·새 Quanta 비밀번호를 제출해야 관리자 계정이 만들어집니다. SMTP 설정 저장 자체는 이메일 인증 성공이 아닙니다.
4. 이후에는 아이디·비밀번호를 사용합니다. 소유자 키는 운영 자동검사·최초 설정·발송 설정 복구용으로 남으며 매번 브라우저에 입력하지 않습니다.

Gmail 앱 비밀번호는 일반 Google 로그인 비밀번호와 별개입니다. Google 계정의 2단계 인증을 켜야 발급할 수 있고 계정 정책에 따라 발급이 제한될 수 있습니다. Google 비밀번호 변경으로 기존 앱 비밀번호가 폐기되면 비공개 발송 설정에서 새 값으로 교체합니다. [Google 공식 안내](https://support.google.com/accounts/answer/185833?hl=ko)를 따릅니다.

## 로그인과 이메일 추가 인증

가입은 6자리 이메일 코드 확인 뒤 완료됩니다. 로그인은 아이디와 비밀번호를 검증하며, 이메일 추가 인증을 켠 계정에는 그 뒤 이메일 코드를 요청합니다. 코드를 확인하기 전에는 정상 세션 쿠키를 발급하지 않습니다.

추가 인증을 켜거나 끌 때도 현재 비밀번호와 새 이메일 코드가 필요합니다. 설정 변경·비밀번호 재설정은 기존 세션과 미완료 코드를 폐기합니다. 비밀번호 재설정 뒤에는 다시 로그인하며, 추가 인증 설정이 켜져 있으면 로그인 코드도 계속 요구합니다.

코드는 요청 목적·이메일·계정 버전·필요 시 현재 세션에 결합하며, 10분 만료·일회 사용·최대 5회 오입력을 적용합니다. 재발급으로 오입력 예산을 초기화하지 않습니다. 최소 재요청 간격은 30초이며 이메일별·전체 발송 요청과 비밀번호 해시 계산에도 제한을 둡니다. 실제 SMTP 발송이 실패하면 그 코드는 사용할 수 없고 명시적인 오류를 반환합니다.

## 서버 보관과 세션

과학 기록은 기존 `jobs.sqlite3`의 여섯 표를 유지합니다. 계정·세션·인증 요청은 같은 비공개 데이터 디렉터리의 `auth.sqlite3`에 별도로 저장합니다. 비밀번호는 무작위 salt와 scrypt 검증값으로 저장하며 원문을 보관하지 않습니다. 현재 비용은 `N=2^17, r=8, p=1, dklen=32, maxmem=256MiB`로 고정하고 동시 해시 계산을 제한합니다.

브라우저에는 32바이트 무작위 세션의 opaque 값만 `__Host-quanta_session` 쿠키로 전달합니다. 서버에는 그 해시만 저장하며 쿠키는 `Secure; HttpOnly; SameSite=Strict; Path=/`를 사용합니다. 유휴 만료는 24시간, 절대 만료는 7일입니다. 로그아웃은 서버에서도 세션을 폐기합니다. 변경 요청에는 고정 Host·Origin·JSON 검사와 세션 CSRF 검증을 적용하며 임의 CORS·프록시 신원 헤더를 신뢰하지 않습니다. 명시적으로 잘못된 Bearer를 정상 쿠키로 대체하지 않습니다.

Gmail SMTP 자격은 `gmail-smtp.json`에, 지속 발송 예산은 `gmail-budget.json`에 보관합니다. 데이터 디렉터리는 0700, 파일은 서비스 사용자 소유의 0600이어야 합니다. SMTP 자격은 발송을 위해 복구 가능한 비밀값으로 보관하므로 계정 비밀번호의 단방향 해시와 구분합니다. 심볼릭 링크·하드 링크·잘못된 권한은 자동 수리하지 않고 거부합니다.

메일은 고정된 `smtp.gmail.com:465`에 검증된 TLS로 연결합니다. 요청자가 SMTP 호스트나 발신 주소를 고를 수 없고, 발신자는 비공개 설정의 Gmail 계정입니다. 앱 발송 시도는 최근 24시간 100회·분당 10회로 제한하고 실패 시도도 예산에 포함합니다. 이 앱 예산은 Gmail의 전체 계정 발송 한도와 별개이며 같은 Gmail 계정의 다른 발송량은 측정하지 않습니다. [Google의 실제 발송 제한](https://support.google.com/mail/answer/22839?hl=ko)을 함께 확인합니다.

## 공개 가입 계정의 자원 한도

일반 공개 계정에는 실험 100개·입력 개정본 500개·최근 24시간 새 실행 20개·동시에 진행 중인 실행 1개·산출물 256MiB의 한도를 적용합니다. 공개 계정 전체의 진행 중 실행은 10개, 산출물은 2GiB, 과학 기록 수는 10,000개로 제한합니다. 실행 접수 때 최대 산출물 32MiB를 예약하고 게시 때 실제 크기를 검사합니다. 재시도는 멱등성 결과를 먼저 확인하므로 성공한 요청을 다시 보내는 것만으로 한도를 소모하지 않습니다. 기존 소유자와 기존 Access 주체는 이 공개 계정 한도의 적용 대상으로 바꾸지 않습니다. 원래의 모듈별 계산 시간·메모리·정밀도 한도는 유지합니다.

## 백업과 버전 호환성

기존 Quanta 일일 SQLite 백업은 `jobs.sqlite3`와 manifest만 포함합니다. 계정 DB·Gmail 발송 자격·발송 예산은 그 사본에 포함되지 않습니다. 현재 사용자가 설정한 OCI 부트 볼륨 백업과 전체 볼륨 복원은 별도 범위입니다. 계정까지 포함하는 서버 복구에는 해당 인증 파일과 기존 소유자 비밀값도 같은 시점의 비공개 복구 대상으로 관리해야 합니다. 이번 기능 때문에 추가 정기 외부 백업을 필수화하지 않습니다.

새 앱은 입력 계약·모형 수식·상수·수치해법을 변경하지 않지만 패키지 버전과 구현 파일 해시가 달라집니다. 이전 실행·결과는 그대로 보존합니다. **같은 환경 재실행**은 저장된 구현과 현재 구현이 다르면 명시적인 오류를 반환하며 조용히 새 환경으로 대체하지 않습니다. **현재 버전으로 새 실행**은 선택한 불변 입력 개정본으로 별도의 새 실행을 만들며 기존 실행의 재현 성공으로 표시하지 않습니다.

## 연결 경계

공개 동일 출처 계정 POST 경로는 `/auth/signup/request`, `/auth/signup/complete`, `/auth/login`, `/auth/login/verify`, `/auth/password/reset/request`, `/auth/password/reset/complete`입니다. 세션에 결합한 `/auth/logout`, `/auth/mfa/request`, `/auth/mfa/confirm`은 서버에서 해당 세션과 CSRF를 확인합니다. `/auth/admin/configure`는 별도의 기존 소유자 Bearer가 필요합니다. 경로는 정확한 목록만 허용하며 계정 API 본문은 8KiB로 제한합니다. 인증코드·비밀번호·SMTP 자격·세션 쿠키를 응답 JSON이나 공개 시험에 넣지 않습니다.
