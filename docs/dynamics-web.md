# 동역학 웹 입력과 3D 저장 궤적

개발 앱0.16.0은 기존0.4 동역학을 브라우저 입력·불변 저장·실행·기록 재조회와 연결합니다. 운영 버전과 실제 반영 상태는 WORKPLAN을 기준으로 합니다. 계산식·모형·단위·수치해법·정밀도·의존성 잠금·기존 계약 원본은 바꾸지 않습니다. 물리 검증은 계속 `unvalidated`입니다.

실험 계약을 명시적으로 선택합니다. 정적·양자는0.2.0, 동역학은0.4.0이며 서버 capabilities의 실제 지원을 확인합니다. 자유입자·조화 쌍퍼텐셜 예제를 추가하고 전체 JSON 편집을 유지합니다. 예제·저장 재조회·내보내기·envelope 가져오기에서 버전과 숫자 원문/signed zero를 보존합니다. bare definition은 이전 기본0.2.0으로 읽고 자동 추론하지 않으므로 동역학 bare 입력에는 사용자가0.4.0을 선택합니다.

## 원본 근거와 화면

실행/결과 양쪽 manifest의 같은 ID·크기·SHA·형식인 solver 보고서를 읽습니다. octet-stream 전송도 지원하며 원본 UTF-8 bytes 크기/SHA-256과 보고서의 실제 payload 전체를 결과 payload와 대조한 뒤 표시합니다. signed zero도 구분합니다. 모형·버전·배열·유한값·ID/질량 순서·시각을 검사하고 잘못된 자료는 명시적으로 거부하며 원본 다운로드를 유지합니다.

2~128입자의 실제 저장 위치를 Canvas2D의3차원 직교 투영으로 표시합니다. 외부 라이브러리·CDN·GPU·빌드는 필요하지 않습니다. 회전·이동·확대/축소·전체 보기·입자 선택, 키보드와 터치를 제공합니다. 표시 원점/길이는 선택한 전체 궤적에 고정해 프레임마다 운동을 숨기지 않습니다. 점 크기·색은 식별용이며 원소·원자 반지름·결합을 추정하지 않습니다. 렌더링 미지원/손실 때 원본 수치와 다운로드를 제공합니다.

| 요소 | 저장 자료와의 관계 |
|---|---|
| 입자 배치·선택 ID/질량·위치/속도/힘 | 같은 프레임의 원본 SI binary64 |
| 처음/끝·이전/다음·타임라인 | 실제 저장 프레임만 선택 |
| 재생·속도 | 물리 시각 비율로 저장 표본 유지, 별도 화면8초 기준 |
| E/K/U·P/L 그래프 | 같은 프레임의 시각 커서·수치 |
| 전 스텝 누적 최대 진단 | 저장 표본 그래프의 최대와 별도 |
| h/h2/h4 | 기본h 우선, 명시적인 비교 선택 |
| 실패·부분 결과 | 마지막 수락 프레임·종료 사유, 성공 최종 상태와 구분 |

합계512프레임 범위를 검사합니다. 저장점 연결 선은 중간 계산 상태가 아니며 보간·실시간 solver 스트리밍은 제공하지 않습니다. 계산 진행과 결과 재생을 구분합니다. 다른 실행/단계·로그아웃·늦은 응답은 세대 검사와 viewer 정리로 처리합니다.

## 검증

Node는 버전/숫자 원문·원본 bytes 바인딩·payload 경계·독립 카메라 투영·큰 공통 좌표/작은 간격·binary64 극값/극소·희소 시각·부분/세분화를 검사합니다. `scripts/verify_dynamics_web.py`의 DWEB01~04는 실제 HTTP·SQLite·별도 계산 자식으로 새 자산/예제·자유입자 독립 해석해·산출물 SHA·기록 재조회·기존 정적/양자를 확인합니다. 실제 브라우저 렌더링을 이 시험으로 대신하지 않습니다.

브라우저 입력→저장→실행→3D/선택 수치/그래프 시각 일치·조작·기록 재열기는 별도 기록합니다. 합성 인증의 격리 preview와 운영 HTTPS 사용자 세션, 좁은 데스크톱과 모바일 실기기를 구분합니다. native ARM/x86·설치 wheel/container·운영 보존/반영은 [검증 기록](dynamics_web_verification.json)과 WORKPLAN의 실제 결과를 따릅니다.
