# 동역학 실험의 실행·저장·재실행

2026-11-06 · 개발 앱0.15.0 · 일반 실험 계약0.4.0 · 독립 solver 계약0.3.1

독립 velocity-Verlet 계산을 기존 실험 정의·실행 계획·SQLite 작업자·HTTP API·결과 산출물·번들 재실행에 연결합니다. 연구자가 입력한 질량·초기 위치·속도·쌍 퍼텐셜·척도·수치 조건으로 동역학 한 단계를 실행하는 범위입니다. 분자 종류·화학 결합·반응 모형을 추가하는 단계는 아닙니다. 실제 운영 배포와 웹3D 화면의 구현 여부는 WORKPLAN에서 구분합니다.

## 버전과 입력

| 경계 | 선택 버전과 지원 범위 |
|---|---|
| 기존 실험·정적/양자 계산 | 기본0.2.0, 기존 입력과 계약 원본 보존 |
| 독립 동역학 요청 검증 | 0.3.0 검증 전용, 원본 보존 |
| 독립 동역학 solver | 0.3.1, 원본 보존 |
| 저장·실행 가능한 동역학 실험 | 명시적 `schema_version=0.4.0`, 첫 등록 모듈은 동역학 |

새0.4 실험은 `definition` 안에 SI·L0/E0/T0·입자계·수치 조건·관측량·빈 확장과 단일 절차를 작성합니다. 절차는 `operation=integrate`, `source=initial`, `overrides=[]`, `sweep.axes=[]`만 지원합니다. 초기 시각은 등록된 어댑터가 명시적으로0으로 매핑합니다. 다단계 연속 실행·분기·임의 시각 재개·정적 결과의 자동 변환은 지원하지 않습니다. 초기 질량이나 속도를 추정하지 않습니다.

```bash
quanta check-contracts --contract-version 0.4.0
quanta validate contracts/v0.4.0/examples/free_revision.json
quanta plan contracts/v0.4.0/examples/harmonic_revision.json --format text
quanta run contracts/v0.4.0/examples/free_revision.json --output-dir .cache/dynamics-run --format text
quanta replay .cache/dynamics-run --output-dir .cache/dynamics-replay --format text
```

작성 입력의 구조·의미·척도·시각·예약 비용은 실제 힘 계산 없이 검사합니다. 초기 힘·미분·보존량의 계산 가능성은 제한된 계산 단계에서 확인한다는 경고를 반환합니다. 저장과 계획 수립이 적분을 먼저 실행하지 않습니다. 실제 적분은 기존 공용 커널과0.3.1 solver를 사용하며 초기 힘을 한 번 평가·재사용합니다.

## 실행·상태·산출물

일반 실험의 작성 정의 해시와 solver에 전달한0.3.1 요청 해시를 분리합니다. 등록된 버전별 매핑, 정확한 solver 계약 전체·정책·원본 해시와 코드/잠금/관측 환경을 실행 계획에 고정합니다. 입력의 계약 버전을 바꿔 부르거나 서로 다른 해시를 같은 의미로 표시하지 않습니다.

초기·준비·성공 출력은 실제 물리 시각을 가진 위상 상태입니다. 일반0.4 상태 envelope 안의 과학 데이터·메타데이터는0.3.1의 질량·입자 순서·위치·속도·척도·시각을 그대로 유지합니다. 시각은 데이터·envelope·과학 해시에 함께 포함합니다. 성공 출력은 기본h 궤적의 마지막 전 스텝이며 실패·미수렴·취소는 성공 상태를 게시하지 않습니다.

실패 전 수락된 궤적은 solver의 부분 결과 규칙을 따릅니다. 실행 중 취소는 진행 중 단계의 미게시 궤적을 폐기합니다. 계산 완료 후 일반 실험의 최종 게시가 실패한 경우에는 내부 계산 결과와 바깥 실행 실패를 구분하며, 내부 성공만으로 후속 상태를 만들지 않습니다. 이미 확정된 단계의 증거가 늦은 전체 취소 뒤 남는 기존 규칙과도 구분합니다.

전체 solver 보고서는 signed zero를 보존하는 원본 UTF-8 산출물로 저장합니다. 과학 내용의RFC8785 해시, 전송 bytes의SHA-256·크기, 작성→실행 요청의 대응 관계를 따로 검사합니다. 궤적뿐 아니라 일반 실행의 계획·상태·provenance·중복 제거한 산출물을 합친 실제32MiB 상한을 적용합니다. 더 낮게 선언된 유효 정책도 지키며 시간간격·정밀도·표본 간격을 자동 변경하지 않습니다.

## 비동기 API와 재현

기존 `/v1/validate`, 불변 revision 저장, `/v1/runs`, 진행 조회·취소·결과·산출물 다운로드·`replay` 경로를 사용합니다. 저장 요청에 `schema_version=0.4.0`을 명시합니다. capabilities는 기존 기본0.2 필드를 유지하고 버전별 지원 모듈과 제한을 별도로 제공합니다. 소유자 분리·계정 한도·멱등성·단일 작업자·재시작 복구는 기존 저장소 규칙을 적용합니다.

감독자와 실제 계산 자식은 수락한 실험 버전·고정 정책에 맞는 시간·메모리 한도를 사용합니다. 강제 중단 때 검증되지 않은 결과를 조립하지 않습니다. SQLite 데이터베이스 스키마 변경은 필요하지 않습니다.

재실행은 불변 초기 입력부터 새 실행·상태 식별자로 계산합니다. 저장한 과거 소스를 실행하지 않으며 현재 구현·계약·환경의 정확한 일치를 확인합니다. 과거 결과 읽기와 현재 구현에서 재실행 가능한지를 분리하고, 기존 결과의 해시를 다시 쓰지 않습니다. solver 체크포인트를 이어 실행하는 기능이 아닙니다.

## 실제 확인 범위

실측 명령은 `python scripts/verify_dynamics_workflow.py --output .cache/dynamics_workflow_verification.json`입니다. 인증된 실제 루프백 HTTP·SQLite·별도 계산 프로세스로 입력/저장/실행, 독립 해석해, 실제 물리 시각, 산출물 bytes, 소유자 분리, 번들 왕복·재실행, 세분화와 drift 오류를 확인합니다. 다른 오류·자원·취소·변조 경계는 관련 시험과 함께 기록합니다.

최종 소스·실제 시험 수·ARM/x86·설치 패키지 근거는 [WORKPLAN](../WORKPLAN.md)과 [검증JSON](dynamics_workflow_verification.json)에 보존합니다. [실제 HTTP·수치 측정](dynamics_workflow_numerical_verification.json)은 별도 기록입니다. D07~D11 전체 또는 웹 화면의 궤적 일치를 일괄 완료로 표시하지 않습니다. 물리 검증은 계속 `unvalidated`입니다. 다음 단계는 이 저장된 궤적·관측량을 3D 입자 화면과 시간 재생에 연결하는 작업입니다.
