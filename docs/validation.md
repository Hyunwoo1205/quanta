# 검증 범위와 해석

## 입력 검증

입력 검증은 계산 제출 전에 적용할 공통 계약과 초기 모듈의 지원 범위를 확인합니다. 순서는 엄격한 JSON 해석, 공통 envelope, 등록 모듈과 전용 스키마, 의미·단위·자원·절차 검사입니다. 구조를 통과한 미등록 모듈도 실행 가능한 지원으로 인정하지 않습니다.

등록 스키마는 동봉된 파일과 URI 등록부에서만 해석합니다. 입력 파일이 임의 경로나 원격 URL을 통해 스키마와 코드를 실행하도록 허용하지 않습니다.

단계 검사는 반복 축으로 만든 분기 정의, 초기 또는 앞선 단계의 정의 승계, 현재 단계 변경값, 전체 재검증 순서를 따릅니다. 실제 계산으로 생성될 미래 좌표와 상태는 이 단계에 존재하지 않습니다. 실행 중 정의역·충돌·수치 유한값·수렴은 향후 계산 엔진에서도 검사해야 합니다.

초기 정의역 검사는 지정한 좌표와 격자점에서의 식 평가를 확인합니다. 임의 수식이 연속 구간 전체에서 매끄럽고 유한하다는 수학적 증명은 제공하지 않습니다. 해당 모형의 가정과 실제 계산 중 검사를 함께 적용해야 합니다.

## 해시

이 구현은 유효한 작성 정의의 `input_sha256`과 RFC 8785 정규화를 제공합니다. 생성 시각·제목·개정본 ID처럼 definition 외부의 메타데이터는 작성 정의 해시에 포함하지 않습니다. 공백이나 JSON 키 나열 순서만 다른 같은 정의는 같은 해시를 가져야 합니다.

실행 계획·실제 단계 입력·상태 내용·실행 지문은 `contracts/v0.2.0/hashing_contract.json`에 서로 다른 대상으로 정의되어 있습니다. 현재 단일 배치 평가는 작성 정의·코드·환경의 근거를 기록합니다. 다단계 실행·상태 관리 시스템이 아직 없으므로 해당 단계의 해시나 미래 상태를 꾸며 생성하지 않습니다.

## 시험의 의미

표준 JSON Schema 검증기, 공식 정규화 기준 자료와 정상·오류 입력의 회귀 시험으로 개발 기반을 확인합니다. 시험이 통과해도 물리 모형의 정확도를 보증하지 않습니다.

첫 `energy_forces` 계산은 독립적인 해석식, 유한차분, 병진·회전·순서 변경, 내부 힘·토크와 SI 동등성으로 검증했습니다. 실제 현상과의 비교는 별도의 물리 검증 근거가 필요합니다. 원본 `validation_manifest.json`은 계획 시점의 자료로 보존하고, 실제 A01~A03 측정은 `numerical_verification.json`에 기록합니다. A04와 다른 계산·실행 기능의 미실행 상태는 유지합니다.

실행 결과의 완료 상태, 수치 수렴, 해상도 수렴, 물리 검증은 서로 다른 정보로 유지합니다. 이 검증기의 `valid=true`는 해당 입력이 지원 계약 검사를 통과했다는 뜻입니다.
