# 소유자 HTTPS 브라우저 확인

2026-11-06 · 앱 0.11.0 · 입력 계약 0.2.0

실제 배포는 Caddy 직접 HTTPS와 명시적 `owner-token` 모드입니다. `PUBLIC_ORIGIN`은 서버에 설정한 실제 HTTPS origin을 뜻하며 이 문서에는 운영 주소나 비밀값을 넣지 않습니다. [실행 42125582058](https://github.com/Hyunwoo1205/quanta/actions/runs/42125582058)은 인증서 발급·화면 응답·익명 및 잘못된 토큰의 401을 확인했습니다. 이어 사용자가 비공개 인증 입력으로 연결한 실제 소유자 데스크톱 브라우저의 계산·기록·다운로드·재실행·취소와 취소 후 재사용·새로고침 재인증을 확인했습니다. 수행 결과와 남은 범위는 [소유자 브라우저 기록](oci_owner_browser_verification.json)에 있습니다.

## 최초 연결

1. 사용자의 기존 신뢰한 PuTTY SSH 세션에서 아래 명령을 실행합니다. 전체 환경 파일 대신 `QUANTA_OWNER_TOKEN`의 값 하나만 그 개인 터미널에 표시합니다. 명령은 파일을 수정하지 않습니다.

   ```bash
   sudo sed -n 's/^QUANTA_OWNER_TOKEN=//p' /etc/quanta/app.env
   ```

2. 본인 브라우저에서 `PUBLIC_ORIGIN`을 열고 HTTPS 주소와 인증서 경고가 없는지 확인합니다. 화면의 **소유자 접근 키** 입력란에 표시된 키를 비공개로 붙여넣고 **연결하기**를 누릅니다. 키를 채팅·공유 화면·스크린샷·저장소·공개 로그·공개 자동검사에 보내지 않습니다.
3. **계산 환경 연결됨** 표시, 패키지 버전과 저장한 실험·실행 목록을 확인합니다. 첫 사용의 빈 목록은 정상일 수 있습니다. 화면이 열렸다는 사실과 인증 후 목록을 조회한 사실을 별도로 기록합니다.

키는 열린 페이지의 메모리에만 보관합니다. 새로고침·연결 해제 후에는 다시 입력하며, 연결 해제는 서버의 실행을 취소하지 않습니다. 새 키·새 SSH 연결 방식·추가 인증 기능을 만들 필요는 없습니다. 키가 출력되지 않거나 연결이 실패하면 값 대신 명령 오류 여부·화면 오류·실패 단계를 보고합니다.

## 실제 확인 항목

개인 검증 기록에는 시간·브라우저·기기 종류, 수행 항목·결과·오류와 필요한 비밀값 없는 실행 식별자만 남깁니다. 현재 데스크톱 확인은 5개 검증 실험·8개 실행이며 키 값은 에이전트에 반환되지 않았습니다. 아래 상태는 실제 관측한 범위이며 원래 수치 기준 전체의 독립 재검증을 뜻하지 않습니다.

| 항목 | 확인할 동작 | 현재 관측 |
|---|---|---|
| 입력·검증·저장 | 지원 예제 또는 입력을 검증하고 불변 revision을 저장합니다. | 데스크톱 5개 검증 실험 저장 |
| 계산 | 저장본을 실행해 진행·종료 상태와 실제 결과를 확인합니다. 실패·부분 결과를 성공으로 바꾸지 않습니다. | 입자 평가·정적 탐색·양자·다단계 완료 |
| 결과 의미 | 실행·수치·해상도·물리 상태와 실제 표·그래프를 확인합니다. | 수치·격자 기준과 네 번째 양자 상태 그래프 확인, 물리 `unvalidated` |
| 기록·다운로드 | 기록을 다시 열고 원본 결과와 산출물을 내려받습니다. | 원본·재실행 기록 보존, 결과 JSON·산출물 1개 다운로드, 기존 UI 크기·SHA 검사 통과 |
| 재실행 | 같은 저장 입력으로 새 실행이 생기고 이전 기록이 보존되는지 확인합니다. | 새 UUID·같은 revision과 입자 결과 확인 |
| 취소 | 실행 중 취소와 종료 상태·확정 결과 범위를 확인합니다. 너무 빨리 끝난 작업은 합격으로 쓰지 않습니다. | 별도 64입자 탐색 `CANCELLED`, 강제 중단 진단·미확정 payload 없음. 빠른 다단계 재실행 완료는 취소 합격에서 제외 |
| 취소 뒤 재사용 | 강제 중단 후 같은 서비스가 다음 실행을 처리하는지 확인합니다. | 새 입자 재실행 완료·기존 revision 및 수치 유지 |
| 재인증·데이터 보존 | 필요한 초안을 내보낸 뒤 새로고침하고 비공개 재인증 후 서버의 저장본·기록을 조회합니다. | 실제 새로고침 후 인증 해제·잘못된 키 거부·수정한 키로 연결·실험 5개/실행 8개 보존 |
| 모바일 | 실제 기기의 비공개 인증·입력·저장·계산·결과·다운로드와 조작을 확인합니다. 화면 폭만 줄인 데스크톱과 구분합니다. | 미확인 |

중복 제출이나 연결 오류가 발생하면 먼저 실행 기록을 조회하고 계산이 수락됐는지 확인합니다. 확인 없이 같은 작업을 반복 제출하지 않습니다. 이 확인을 위해 앱·방화벽·백업·ACME를 다시 설치하지 않습니다.

이 문서는 확인 절차와 현재 진행 범위를 연결합니다. 다운로드는 브라우저 동작과 기존 UI 검사를 확인한 것이며 내려받은 파일의 외부 독립 해시 검증을 수행했다고 표시하지 않습니다. 새로고침·같은 서비스의 후속 계산 처리은 실제로 확인했으며 모바일은 미확인입니다. 새로고침 후 최초 재입력은 사용자가 잘못된 키였다고 확인했고, 사이트가 이를 거부한 것은 정상 인증 동작입니다. 수정한 키의 비공개 재인증 후 **계산 환경 연결됨**·v0.11.0과 완료 7개·취소 1개를 확인했습니다. 같은 부트 파일시스템 안의 기존 분리 복구 성공은 off-host 백업·전체 볼륨 복원·실제 OS 재부팅 검증을 뜻하지 않습니다.
