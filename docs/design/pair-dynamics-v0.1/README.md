# 첫 동역학 모듈 설계 기준 0.1.0

2026-11-06 · **설계 기준, 미구현·미등록·미배포**

설명 원본은 기존 [개인용 세부 명세](https://docs.google.com/document/d/1t0SUe1Z3tYB5rlpnujeguBRqIQzxuAynOcCxLk27tIQ)의 동역학 설계 절에 있습니다. 이 디렉터리는 구현에 사용할 기계 판독 명세·스키마·입력·시험 계획입니다. 현재 앱0.12.0·활성 계약0.2.0·물리 상태unvalidated는 바꾸지 않습니다.

## 파일과 해석

| 파일 | 의미 |
|---|---|
| design.json | 선택한 범위·법칙/모형/해법·의미 규칙·자원·실패·활성화 순서 |
| request.schema.json | 독립 solver 호출 입력 초안. 현재 실험 definition/envelope가 아님 |
| payload.schema.json | 동기화된 궤적 payload 초안. run·실행 상태·artifact envelope가 아님 |
| harmonic.request.json | 질량이 다른 두 입자의 비공선 조화계 입력 |
| harmonic-refinement.request.json | 같은 종료시간 h/h2/h4 검증 요청 |
| free.request.json | 비충돌 자유운동 기준 입력 |
| validation-plan.json | D01~D11 독립 수치·구현·실패·통합 합격 기준. 모두 미실행 |
| references.json | 공식 해법 출처와 실제 확인 버전·용도 |
| SHA256SUMS.json | 이 설계 파일들의 원본 바이트 SHA-256; 자기 파일 제외 |

미지원 입력을 0으로 채우거나 질량·속도를 추정하지 않습니다. 법칙은 Newton 방정식이고, 모형은 3차원 비주기 공간의 동일한 거리 의존 쌍 퍼텐셜입니다. 모든 입자는 자유이며 외력·열조절·거리 절단은 없습니다. 이는 고립계 시간적분의 첫 범위이며 통계적 NVE 앙상블 표본화나 실제 물질의 정확도를 주장하지 않습니다. 다른 모형·경계·입자 수로의 플랫폼 확장을 막는 공통 제한이 아닙니다.

## 의미 검증과 출력

스키마만으로 입자 ID 중복, 같은 N의 배열 형상·순서, 유한 binary64, 척도 변환 가능성, AST 깊이/노드/계수 참조, 최소거리, 시각 격자 증가, 전체 자원 및 성공/부분 출력 조합을 증명하지 못합니다. `design.json`의 의미 규칙도 적용해야 합니다.

시간 간격·스텝 수·출력 간격은 필수 입력입니다. 각 leg의 SI·무차원 시간 간격과 half-step은 양의 유한값으로 표현 가능해야 하며 nonzero underflow는 오류입니다. 시간은 누적 덧셈하지 않고 정수 인덱스와 입력 dt의 정확한 binary64 값을 사용해 계산합니다. 위치·속도·힘·K/U/E·P/L은 같은 full step에 대응합니다. 출력 프레임 수와 관계없이 보존량 최대 편차는 모든 수락 스텝에서 누적합니다.

refinement=halving_2는 동일 초기 상태에서 h,n / h/2,2n / h/4,4n을 실행합니다. 기본 궤적은 요청한 h를 유지합니다. 비교는 보간하지 않은 모든 기본 정수 스텝에서 수행합니다. 저장은 각 leg의 공통 표본 시각에 한정하며 세 궤적을 모두 보존합니다. 두 인접 비교가 모두 목표 이내이고 finer 차이가 coarse 차이보다 크지 않아야 해상도 기준을 통과합니다. 이는 시간 해상도 일치의 유한 근거이며 일반 입력의 정확도 보장이 아닙니다.

P=N(N−1)/2, 기본 스텝 n, 표본 간격 s, leg 수 L=1 또는3일 때 평가 수는 n+1 또는7n+3, 기본 프레임 F=1+ceil(n/s)입니다. 미표본 마지막 수락 상태의 부분 결과를 위해 leg당 한 프레임을 추가 예약해 L(F+1)≤512를 검사합니다. 총 평가≤10,000, P×평가≤1,000,000이며 원래 단계60초·전체120초·메모리1,024MiB·산출물32MiB를 유지합니다. 자원 내 입력도 완료 시간은 보장하지 않습니다. 궤적 예약 상한은 `reserved_frames * (25*(9N+15)+8N+1024)+65536` bytes로 계산합니다. 정확한 전체 실행 provenance·입력·종료 기록 bytes를 따로 산입하고 마지막 게시 전 실제 bytes를 다시 검사합니다.

초기 힘/정의역 오류에는 payload가 없습니다. 나중의 오류에는 마지막 완전 수락 상태만 부분 결과가 될 수 있습니다. 실패 trial·half-step 속도는 정상 상태가 아닙니다. 구조·정의역·유한값 검사는 매 스텝의 수락 조건이고, E/P/L 허용오차는 중간에 초과해도 임의 중단·보정하지 않고 전체 요청 leg를 마친 뒤 최대 편차로 판정합니다. numerical 또는 resolution 기준 미충족은 실행 FAILED·유효한 궤적 partial이며 성공 상태를 게시하지 않습니다. 모든 기준 통과 때만 primary factor1의 최종 phase state를 게시합니다. 취소 시 자식 프로세스의 미게시 메모리 궤적이 보존된다고 약속하지 않습니다. 완료된 산출물 보존과 solver 체크포인트 재개는 구분합니다.

## 기존 계약과의 연결

현 계약의 일반 envelope는 evolving time을 표현할 수 있지만 현재 등록부·validator·runner는 동역학을 지원하지 않습니다. 활성0.2 번들을 덮어쓰지 않고 미래0.3.0 번들에 새 스키마 ID·상태·포트·관측량·자원 프로필·등록부·해시·resolver/패키징을 함께 도입하는 설계 결정을 택합니다. 현재 이 파일은 그 활성 번들이 아닙니다.

첫 활성화는 단일 integrate/source=initial 단계이며 sweep·override·연속 단계·정적→동역학 자동 변환을 지원하지 않습니다. 임의 시각 재개와 상태 전달은 이후 명시적 계약으로 확장합니다. 최종 phase state의 과학 데이터에는 실제 time_s를 포함하고 envelope physical_time과 일치시켜 시간까지 해시 대상으로 삼습니다.

현재 `_PreparedPair`는 정적 module_id와 정의를 강제하므로 dynamics 입력을 이름만 바꿔 통과시키지 않습니다. 후속 구현에서 공용 내부 힘 커널을 추출하고 기존 에너지·힘/relax 회귀를 먼저 확인합니다. `validation.py`, `planning.py` dispatch, `workflow.py`의 static 시간 하드코딩·상태 조립, 결과 검사·서비스 capabilities를 정확히 확장해야 합니다. 스키마 추가만으로 실행이 지원됐다고 표시하지 않습니다.

구현 순서는 새 번들·검증 → 공용 힘 커널 → VV와 실패 경계 → 독립 수치검증(x86/ARM) → 단일 단계 실행/API/저장/취소/재현 → 웹·시각화입니다. 과거0.2 입력·번들·구현 해시는 그대로 보존하고, 새 구현으로 실행할 때는 별도의 새 run을 만듭니다.

## 설계 일관성 확인

```bash
.venv/bin/python scripts/check_dynamics_design.py
```

이 명령은 일부 설계 일관성을 확인하는 보조 검사이며 완전한 solver 입력·출력 의미 검증기가 아닙니다. 스키마·선택한 입력 수락/거부·예약 예산·독립적인 초기 보존량 상수·구조 확인용 합성 payload·파일 해시와 비활성 등록 여부를 검사합니다. 임의 AST의 초기/진행 중 정의역과 실제 궤적 품질은 검사하지 않습니다. 시간적분 solver를 실행하지 않으며 D01~D11을 합격 처리하지 않습니다. 실제 모듈 수치 검증은 구현 후 별도로 남깁니다.
